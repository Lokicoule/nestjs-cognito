# @nestjs-cognito/testing

Testing utilities to mock Cognito authentication in NestJS applications.

## Installation

```bash
npm install -D @nestjs-cognito/testing
```

## Module

### `CognitoTestingModule.register(config, mockConfig?, options?)`

- `config`: `CognitoModuleOptions`, used in real mode.
- `mockConfig`: `MockConfig`. With `enabled: true`, tokens are issued locally and no request reaches Cognito.
- `options`: `CognitoTestingOptions`, e.g. `clientSecret` for app clients with a secret.

`registerAsync(options, mockConfig?, testingOptions?)` takes `CognitoModuleAsyncOptions` instead of `config`.

### `CognitoTestingModule.createJwtVerifierFactory()`

A JWT verifier that decodes tokens without checking their signature, and rejects expired ones. Use it to override the real verifier in tests:

```typescript
Test.createTestingModule({ imports: [AppModule] })
  .overrideProvider(COGNITO_JWT_VERIFIER_INSTANCE_TOKEN)
  .useFactory({ factory: CognitoTestingModule.createJwtVerifierFactory })
```

## Services

### `CognitoTestingService`

- `getAccessToken(credentials, clientId): Promise<AuthenticationResultType | undefined>`: logs in (mock or real Cognito) and returns `AccessToken`, `IdToken` and `RefreshToken`.
- `setMockConfig(config: MockConfig): void`

### `CognitoMockService`

- `getMockTokens(clientId): AuthenticationResultType`: tokens for the mocked user, shaped like Cognito's. The access token carries `client_id`, `username` and `scope`. The ID token carries `aud`, `cognito:username`, `email` and the custom attributes. The refresh token is opaque.
- `createClientCredentialsToken(clientId, scopes): string`: a machine-to-machine access token.
- `verifyToken(token): TokenPayload`: throws if the token is invalid or expired.

## Types

```typescript
interface MockConfig {
  enabled?: boolean;
  user?: MockUserConfig;
  expiresIn?: number; // seconds, default 3600; negative issues expired tokens
}

interface MockUserConfig {
  username: string;
  sub?: string;       // defaults to the username
  email?: string;
  groups?: string[];
  scopes?: string[];  // defaults to ['aws.cognito.signin.user.admin']
  attributes?: Record<string, string>; // e.g. { 'custom:tenant': 'acme' }
}

interface CognitoTestingOptions {
  clientSecret?: string | (() => string | Promise<string>);
}
```

## Endpoints

### `POST /cognito-testing-login`

Logs in and returns the tokens.

**Request:** `{ username: string; password: string; clientId: string }`

**Response:** `{ AccessToken, IdToken, RefreshToken, TokenType, ExpiresIn }`

### `POST /config`

Replaces the mock configuration. **Request:** `MockConfig`.
